# Experiment 3: does a long lessons file hurt? (2026-10-12)

Question (work list item 6, `docs/progress.md`): with 500 correct-looking but unrelated lessons in `.ludion/lessons.md`, does accuracy on the B questions drop by 10 points or more? If it does, sync would also write per-subject skills (`.agents/skills/ludion-<subject>/SKILL.md`) that load only when relevant.

## Setup

- Same as Done 3's B measurement (`../2026-10-11-done3/`): the 45 B questions, Claude Code (`claude-opus-5-5`) with its default tools in the prepared projects, the frozen seeds (commit `7d61ed1`) served locally, an empty ledger, the same opus judge.
- One difference for all three conditions: `ludion sync` is the CLI built from main at `e7d82d7`, so `lessons.md` has the partial-coverage line (#53).
- After sync, `tools/bench/src/unrelated.ts` adds N lessons about other packages, merged in sync's own order (silent, loud, added; then package name), so the relevant lessons sit among them as in a project with many covered dependencies.
- The pool (`pool.json`, 973 blocks, frozen before the runs): claims generated by `generateClaim` from the seed pipeline's triage of nine other packages (ai, @anthropic-ai/sdk, astro, eslint, express, hono, next, nuxt, openai; their triage is in `docs/bench/2026-10-12-subjects/` on the `seed-pipeline` branch until it merges), taken round-robin across packages, each with the same teacher line as a seed. **They are not verified lessons**: each is a triaged changelog entry turned into a claim, and its "verified" label is simulated so the file looks like a real one. They exist only in this experiment.

## Results

| unrelated lessons | correct | cost of the 45 answers |
| - | - | - |
| 0 | **40/45** | $5.76 |
| 50 | **41/45** | $6.99 |
| 500 | **41/45** | $23.11 |

One trial per question per condition. No drop was seen: 500 scored one more than 0, where the rule asked for 10 points fewer, so **skill delivery is not built** (`docs/decisions.md`). With one trial, runs of the same setup differ by up to 4 of 45 here (the 0 condition against the official run), so this rules out a large drop, not a small one.

- Cost grows with the file: 500 unrelated lessons made the 45 answers cost about four times as much, from the longer context in every turn.
- Against this experiment's own 0 condition: vitest-5-0-0-16 (`vi.mock` inside `beforeEach`) is correct at 0 and wrong at both 50 and 500, with the same mistake both times. It is the only loss that repeats, and a second possible sign of a lesson getting lost in a long file.
- Against the official B with-sync run (`grades-B-project-sync.json`): at 0, agents-0-20-0-18 (the answer got the `createMcpHandler` factory right but imported `McpServer` from the old package, which no lesson mentions: run-to-run variation); at 500, vitest-5-0-0-5: the answer got the core right (the runner is folded into `vitest`) but said the package isn't deprecated, and it says it found no changelog entry confirming the change, although the seed for it was in the file. That is the one sign in these runs of a lesson getting lost among 500 others. wrangler-4-113-0-21 is wrong at 0 and 50 (no answer in the official run) and correct at 500: the frozen site still serves the provisioning seed that the harm check withheld from main.
- The 0 condition is also a reference re-run of Done 3's B with the partial-coverage line: 40/45, against the official 36/45 without it. One trial each; reference only (`docs/decisions.md`, "Measuring Done 3").
