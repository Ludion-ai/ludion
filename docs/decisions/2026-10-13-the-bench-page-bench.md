### 2026-10-13: The bench page (`/bench`)

- **`/bench/` replaces `/models/`.** `/models` and `/models/` redirect to it (301, `apps/site/public/_redirects`), and the nav says "Bench". `/models/`'s content (models.json: per model and per lesson, knows or misses) moved into it as the "Without tools" section. `bench` and `bench.json` joined `RESERVED_SUBJECTS`; `models` stays reserved, since it still redirects.
- **One reader, `apps/site/src/build/bench.ts`**, like `models.ts`: the official Done 3 run (`docs/bench/2026-10-11-done3/`: questions, answers, grades, seeds, logs) and `models.json`. No number on the bench pages is typed in: each cell is counted from the grades files, each cost summed from the `costUsd` of every answer and grade, and the measuring date is the run folder's date. A test recounts every cell from the raw files and checks the totals against the Done 3 README's headline.
- **The table**: a row per model and condition, a column per subject and one for all. A cell is correct answers out of questions with its 95% Wilson interval, printed and drawn to scale on a 0–100% line. Scores are never colored (the site has no hue); differences are read from the intervals. The condition (tools, web search on or off, `ludion sync` on or off) is in each row. A model in `models.json` with no Done 3 run gets one "Not measured" row, after the measured ones; nothing is estimated. The page says when it was measured and how many days ago (counted again in the browser, so it stays right between deploys).
- **The without-tools table** counts lessons, not questions: the measured, active lessons whose change the model answered right twice, the rule sync prunes by. Its caption says so, so the two tables' units aren't confused.
- **`/bench/<model>/`**: the model's rows, every Done 3 question it didn't get right per condition (subject, grade, the change's seed lesson from `seeds.json` linked to `/lessons/<id>/`, or "no lesson for this change", or "its lesson was not published" for the withheld seed), every answer's grade linked to its log, and the lessons it misses without tools.
- **`/bench/<model>/<question>-with-sync/` and `-without-sync/`**: the question, the answer key, the answer, the grade and the judge's reason, and the session log read from `runs/<label>/<question>.jsonl`: the agent's text, each tool call with its input, and each tool's output (cut at 20,000 characters, with a note and a link to the raw file). The init line, thinking, and rate-limit events are left out. B questions run no container: the "output" is what Claude Code's tools returned. Logs are untrusted text (web pages, package files) and are rendered escaped, never as HTML. These pages are `noindex` and not in the sitemap.
- **`/bench/method/`** is `docs/bench/README.md` (new: how questions are made, graded, the conditions, cost), rendered by Astro at build time, plus a cost table summed from the run files. The README's links are absolute so they work on GitHub and on the site.
- **"Run it again"** is one line built from the run's files. The run with sync must use the CLI and lessons frozen for it (the commit is read from the run's README, "frozen at commit `…`"), served locally through `LUDION_SITE`, never today's ludion.ai, whose lessons have changed since; the line and its note say so, and the table's caption names the frozen commit and the number of seed lessons (`seeds.json`). (From the review of #96, which found the first version of the line would have synced from production.)
- **`/bench.json`**: both tables as data, with the interval's definition and links to the run folders.
- **Share cards** (the build fails if a card page has no image; a test checks the built files too): `/bench/og/<model>/` is a bare 1200×630 page with the model's table only (measured in a project if it was, else the without-tools table with "Not measured in a project yet"). After `astro build`, `apps/site/scripts/og.ts` serves `dist` on 127.0.0.1 and screenshots each card with Playwright's Chromium into `dist/bench/og/<model>.png`, next to the rest of the build; `/bench/<model>/` names it in `og:image` and `twitter:card` (`summary_large_image`). So `npm run build` needs Chromium: `test.yml` installs it before the build (it was installed after, for e2e only), and `deploy.yml` installs it before its build step.
