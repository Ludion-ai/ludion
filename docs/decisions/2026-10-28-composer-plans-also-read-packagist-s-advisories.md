## 2026-10-28 — Composer plans also read Packagist's advisories

The owner asked that Composer planning read Packagist's advisories as well as OSV, and take the later of the two fixed versions. Packagist's advisory API (`https://packagist.org/api/security-advisories/`, the source `composer audit` uses) carries FriendsOfPHP and vendor feeds, which can be published before OSV has them or end a range at a later fix.

How: `packages/cli/src/security/packagist.ts` reads the advisories for the inventory's Composer package names only (no versions, no source), with the same limits as the OSV client (fixed origin, no redirects, 20s deadline, 4 MiB body, strict record shape). Each advisory becomes an OSV-shaped record whose fixed events are the exclusive upper bounds (`<x`) of its affected ranges, and it is a finding only when its range contains the installed version. The existing smallest-fix planning then takes, per package, the highest of the smallest same-major fixes over both sources. A planned version that Packagist still lists as affected moves to the end of that range; if there is none in the same major (same minor for 0.x), the package is blocked. Any lookup failure or malformed answer fails the scan, as for OSV; an affected range Ludion cannot read (stability suffixes, four-part versions that are not `.0`) blocks that package and makes the scan incomplete. The post-candidate re-scan uses the same code, so a candidate Packagist still lists as affected is not applied. npm and Maven do not query Packagist.
