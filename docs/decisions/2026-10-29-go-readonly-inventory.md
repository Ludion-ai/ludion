# 2026-10-29: Go read-only inventory (go.mod)

`packages/cli/src/security/readonly/go.ts` reads go.mod for a read-only OSV scan (ecosystem `Go`). Nothing is patched.

- **Inventory source: go.mod's require list.** Since Go 1.17 it names every module the build needs; `// indirect` (Go's own rule: the comment is exactly `indirect`, or starts with `indirect;`) gives `direct: false`. go.sum is not the inventory: it also records checksums of modules outside the build list. A `go` line older than 1.17, or none (Go then assumes 1.16), is a limitation: the require list may be incomplete.
- **Versions exactly as go.mod writes them.** OSV matched golang.org/x/text at `v0.3.5` and `0.3.5` the same (GO-2021-0113 among six), pseudo-versions and `+incompatible` with or without the `v`. Only full versions (`v1.2.3`, prerelease, `+incompatible`) are accepted; `v1.2`, `latest` or other build metadata throw.
- **Replaced requirements are left out, never substituted.** The build does not use the original, and Ludion does not check the replacement: a local directory and a module@version replacement each become a limitation (the second names both). A replacement for the exact version wins over one for every version, as in Go. A required path with no dot in its first element, unreplaced, is a limitation too (Go cannot download it; this also keeps a module named `stdlib` from being queried as the standard library).
- **The Go distribution only from a `toolchain goX.Y.Z` line**, as two OSV packages at `X.Y.Z` (no `go` prefix; OSV does not match `go1.22.5`): `stdlib`, the standard library compiled into the program, and `toolchain`, cmd/go and the other build-time commands (for example GO-2023-2042, code execution through the toolchain directive). The `go` line is a minimum, not the toolchain in use, so without a toolchain line, with `toolchain default`, a non-release name (rc, custom suffix) or a toolchain older than the go line, neither is checked and a limitation says so. The scope says that under the default GOTOOLCHAIN=auto a newer installed Go, or a GOTOOLCHAIN setting, builds instead.
- **exclude and retract** are validated and ignored. godebug, tool and ignore are validated and ignored. An unknown directive is a limitation, not an error, so a newer Go's directive does not stop the scan; malformed syntax throws with its line number.
- **go.work** in the project root is a limitation (its modules and replacements are not read).
