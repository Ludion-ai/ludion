# 2026-10-29 (L1c) — The one fix: an image that copies single package folders out of node_modules

Under 2026-10-29-l1c-new-sample.md, section 1. Committed with the code and the measurement script, and pushed before the new sample's search runs. Nothing here changes section 2 of "Gate 1's production/dev split, rebuilt", the gates or the wait table.

**What step 1 found** (docs/bench/2026-10-29-l1c, `result/undecided-main.json`, computed offline over the rerun's own data). Of the 938, the split made 11 (repository, package) pairs production only because it fell back. All 11 come from the D1-only fallback for a production image holding devDependencies, in 3 repositories. The other readings the task names are not where the count comes from:
- an incomplete source tree: 0;
- a nested package.json that is not a lockfile folder: 1 pair, in ruddyribera-ops/pria-app (`server/`);
- an import no node_modules up the path resolves, which seeds every copy of the name: 0;
- bin names that seed copies nested in another package: 0;
- bundledDependencies: in 20 counted pairs every vulnerable production copy is bundled (`inBundle`). Section 2 has no rule of its own for bundled copies, so they are production by the same rules as any other copy;
- following peerDependencies (25 pairs) and optionalDependencies (3 pairs): section 2's "Following" names both, so these are not undecided cases.

**The fix.** A COPY whose source is one package's folder in node_modules (`COPY --from=builder /app/node_modules/pino-pretty ./node_modules/pino-pretty`) no longer counts as copying node_modules. Section 2 says a final stage holds devDependencies when "it copies `node_modules`, or a stage's whole working folder, from a stage that holds them". The code matched `node_modules` anywhere in the source path, so one package's folder made the whole lockfile D1 only. Now:
- the image holds that package. Every installed copy of the name, and every copy nested under one of them, is production ("held by <Dockerfile>'s final stage"). Section 2's D2 calls a copy dev-only only when "the production image does not hold it", and following applies from these copies as from any production copy;
- the image is not, for that COPY alone, a production image holding devDependencies, so D2 can apply to the rest;
- anything else still counts as copying node_modules: node_modules itself, `.bin`, `.prisma` or any other dot folder, a wildcard, a scope alone, a path inside a package. So does a package folder copied together with any of those, or with the working folder or `.`;
- the names a stage holds pass to the stages built FROM it and to stages that copy it whole. They are collected in one linear pass (a test checks 16,000 stages).

Effect on the original 100, offline (`result/undecided-fixed.json`): 938 → 935. The 3 pairs are brace-expansion, joi and shell-quote in developer3000S/OmniRouteRus. Its final stage copies `.next/standalone` and four package folders (`@swc/helpers`, `pino-abstract-transport`, `pino-pretty`, `split2`) from a builder that ran `npm ci`. The other 8 fallback pairs stay production (see below).

**Considered and not made.** In each case the files cannot show that the copy is dev-only, so it stays production ("when in doubt, production"):
- **A nested folder with its own package-lock.json** (pria-app's `server/`, 1 pair). Its own install would put the nearest copy in `server/node_modules`, but nothing in the files shows that install happens before the code runs or is bundled. Without it, Node resolves the root's copy.
- **pria-app's `server/Dockerfile`** (2 pairs) runs `COPY package*.json ./`, `npm ci` and `COPY . .`, and its build context is not in the files. With the repository root as context, it holds the root lockfile's devDependencies.
- **jadwalit-jpg/Jadwal's `apps/api/Dockerfile`** (6 pairs). Its deps stage runs `npm ci --omit=dev` and then `npm install --prefix /tmp/sharpfix … <tarballs>` without `--omit=dev`. Section 2's text counts every non-global install without one of the listed flags, whatever its `--prefix`. Its final stage also copies `node_modules/.prisma`. Reading `--prefix` as "not this project" would narrow section 2's words.

**Changed after the search was saved (a deviation from section 1 of 2026-10-29-l1c-new-sample.md).** The fix was committed and pushed as 7891feb before the search ran. The search was saved at 2026-10-28T18:07:37Z and committed as a8ba24d. After that, the automated security review of 7891feb found two places where the fix left out copies the image may hold:
- an `ADD` whose source is under node_modules (ADD can unpack an archive);
- a folder whose name is an npm alias (`node_modules/my-lodash` installing `lodash`), which was looked up by package name.

Both now fall back toward production. Only `COPY` reads a package folder. A held folder is found by its install path, so an alias counts, and a held folder that is no installed copy's path leaves the image holding devDependencies. This was changed before any of the search's data was read, beyond the per-hour totals that `join.mjs` prints, and before either measurement started. It can only make more copies production. Its effect on the original 100 is none (still 935, `result/undecided-fixed.json`). Both measurements run at the commit that adds this paragraph.
