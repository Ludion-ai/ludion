## 2026-10-29 (LP-rest) — The action follows judge-comment.yml; changed workspace package.json files are passed; LICENSE, Node 22 and packed file modes; Dependabot leaves examples/ alone

The protected-path PR "LP" (night v2, §5), the part that is not protected-paths.yml. #166's last review (Non-blocking 1 and 4), L4's report (owner items 3 and 8) and L9's report (item 2) asked for these.

- **The comment job in judge-comment.yml's order (#166's N6).** action/comment.sh now finds the PR from GitHub: the open PRs from the run's head owner and branch into the default branch, of which exactly one must come from the run's head repository and branch and be at the run's head (action/pick.jq, a copy of judge-comment.yml's PICK). It then reads what that head changes (`compare/<default branch>...<run head>`), and only when that head is not refused does it list, download and check the artifact, which must name the same PR and head. A refused head's comment is rendered from `$head` with no record, as judge-comment.yml's is (action/body.jq). action.yml passes `RUN_OWNER` and `DEFAULT_BRANCH`. packages/cli/test/action.test.ts runs comment.sh against a stand-in for gh with the cases of judge-comment.yml's script test, and checks that valid.jq, pick.jq and refuse.jq are judge-comment.yml's programs and that body.jq differs only in its preview line.
- **Changed workspace package.json files are passed to the judge (L9's wiring, its workflow half).** judge.yml (with git) and action/read.sh (with the API) copy each changed path that ends in `/package.json` into `before/` and `after/` at the same relative path, on each side whose commit has it: judge.yml asks git; read.sh goes by the compare answer's status (added and copied: after only; renamed: the new path after, the old path before; removed: before only). A path with an empty, `.` or `..` segment stops the read, so the record says the read failed (undecidable). Today's judge reads only the root files, so verdicts do not change; L9 (#174) wires the rule that reads them. Until then a PR that changes a workspace's package.json still stops at gate 4. README's limits say so.
- **LICENSE in the npm package.** packages/cli/LICENSE is a copy of the repository's LICENSE (a test keeps them equal), listed in `files`. publish.yml's Pack step still expects exactly README.md, dist/cli.js and package.json, so a publish now fails at that check, before staging. That is the safe direction; the owner adds `package/LICENSE` to that list (a protected path this PR does not change, by assignment).
- **The same tarball from any checkout.** npm pack takes each file's mode from the disk, so L4's pack from a Windows checkout had 0755 and a different integrity. packages/cli/build.ts now sets dist/cli.js, LICENSE, README.md and package.json to 0644 after building. Checked: a pack, then a pack after setting the four files to 0755 and building again, gave the same bytes (docs/bench/dogfood/npm-pack.md, "Again after LP-rest").
- **Node 22.** Node 20 reached end of life on 2026-04-30. packages/cli's `engines` is `>=22` (and its lockfile entry, which `npm install --package-lock-only` leaves unchanged), both bundles target `node22`, and action/start.sh refuses a runner below 22. The repository itself stays on Node 24 (.node-version, root `engines`).
- **Dependabot and examples/\*-security.** The examples are owned fixtures pinned to vulnerable versions on purpose (application smoke tests for Ludion's own scan and patch). Dependabot opened security updates on them (#171 to #173). GitHub's options reference marks `exclude-paths` as version updates only and `ignore` as also applying to security updates, so .github/dependabot.yml gets one entry per example (npm, composer, maven) with `ignore: dependency-name: "*"`, and `open-pull-requests-limit: 0` for version updates. examples/php-security (a Dockerfile) gets none: no Dependabot PR has been opened for it. Whether this stops new security PRs can only be seen on GitHub after this is on main. It does not close #171 to #173.
