## 2026-10-29 (LP-rest) — Records are one file each; decisions.md and progress.md move, word for word

Fixed before the move was run. From the night of 2026-10-28 (v2) many sessions write records at once, and every one of them appended to the end of docs/decisions.md and docs/progress.md, so every pair of PRs conflicted there.

- **The rule.** One record per file. A decision is a new file `docs/decisions/YYYY-MM-DD-<topic>.md`; a result is a new file `docs/progress/YYYY-MM-DD-<lane>-<topic>.md`. Detailed records stay in the work's own folder under docs/bench/. docs/decisions.md and docs/progress.md are not appended to; each becomes an index of the moved entries. CLAUDE.md says this (its "Engineering and security" section, the first bullet).
- **What moves.** Every entry in the two files at the commit this PR is merged onto, as it stands, with not one character changed: the heading, the body and the blank lines after it. Nothing is merged, summarised, re-dated or corrected on the way.
- **Where an entry starts and ends.** An entry starts at a `##` heading, or at a `###` heading that begins with a date (`### 2026-10-12: ...`). It runs to the line before the next such heading, or before the next `#` heading, or before the old decisions.md introduction (the paragraph that begins "CLAUDE.md is the spec."). So an undated `###` heading stays inside the entry above it (for example "### Security preview — independent review corrections" stays with "## 2026-10-27 — Security-update source preview", and "### Conventions" stays with "## Carried over from v0").
- **What stays in the index.** Parts that are not entries are kept, as they were, in the index: the `#` title, a `##` heading with nothing under it but the entries that follow (decisions.md's "## v2 decisions", progress.md's "## Log"), and decisions.md's old introduction, whose rule ("Newest decisions go at the top of their section … edit it here") this decision replaces.
- **File names.** The date is the first `YYYY-MM-DD` in the heading. An undated section takes the date its heading was committed (`git blame`): "## Carried over from v0" and "## Done when (CLAUDE.md)" 2026-10-12; "## Current work: batch mode (from 2026-10-12)" 2026-10-12. The topic is the rest of the heading, lower-cased, with a parenthesis right after the date (such as "(cycle 2)" or "(evening)") left out, every run of other characters made one hyphen, and cut at a hyphen to 60 characters at most. In progress/, the lane is the one the heading names ("(cycle 3, L4)" gives `l4`, "(cycle 3, LS)" gives `ls`); an entry that names none gets `moved`. A name already taken gets `-2`, `-3`.
- **The index.** Each moved entry is one line in the old order: its heading text, linked to its file. So a reference such as (docs/decisions.md, "Publishing") still finds its entry by title.
- **The check.** Putting the kept parts and the files' contents back together, in the index's order, gives the old file byte for byte; the line counts add up the same way. The script (docs/bench/2026-10-29-lp-rest/split.mjs) does the move and the check, in Docker; its output is saved next to it. The check is run again after the last merge of main before this PR is merged, so entries other PRs add before then move too.
- **History.** `git log --follow` does not follow a split. The commit before the move is named in each index, and `git blame -C -C` finds a line's origin across it.
