# 2026-10-29 — Rust, read only: what Cargo.lock can and cannot show (#183)

- **What is read.** `readRust` reads Cargo.lock (formats 1 to 4) and reports only crates.io registry packages, by name and version. Packages without a source are the project itself (workspace members and path crates) and are not inventory. A crate one of them names in its `dependencies` is direct. Ids are resolved as Cargo's `lookup_id` does (`src/resolver/encode.rs`): a name alone needs one version, a source is matched exactly without its `#commit`, and an id without a source prefers a single path package. Git, other-registry and recorded-path crates, crates replaced through `[replace]`, and an unknown format version are limitations. Anything malformed throws.
- **No source in any message.** Git URLs can carry credentials (`user:token@`), and these messages reach CI logs and `--json`. So no error or limitation contains any part of a source, nor a quoted key (v1 `[metadata]` keys embed sources). Sources are described by kind only (crates.io, a git source, another registry, a recorded path).
- **A removed source line.** Cargo writes a checksum only on a registry package, so a package with a checksum but no source is refused. A registry package whose `source` and `checksum` lines were both removed reads as a path crate and drops out of the inventory without a limitation. The lock alone cannot reveal this; only a cross-check against the workspace's Cargo.toml files could. When Cargo meets such an entry, it drops it and resolves again, so that lock no longer describes the build.
- **Bounded work.** Resolution is indexed once, so each dependency id costs a constant number of lookups, and a repeated id is read once. A 4 MB lock file of the review's hostile shape takes well under a second; it took 79 s before the fix.
