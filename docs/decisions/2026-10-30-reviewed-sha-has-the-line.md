# 2026-10-30 — A review has the line reviewed-sha:, it need not end with it

**Owner decision, 2026-10-30**, approved by the owner (「OK」): the rule on recording a review says that the review's comment has the line `reviewed-sha: <the head SHA reviewed>`, instead of that it ends with that line. This replaces the wording "ends with" of docs/decisions/2026-10-28-every-review-is-recorded-on-its-pr.md and "ending `reviewed-sha:`" of docs/decisions/2026-10-28-two-rules-into-claude-md-the-follow-ups-to-156-157-and-158-s.md, which both stay as they were; the rest of those decisions is unchanged. CLAUDE.md (Engineering and security, Reviews) and docs/protected-paths.md (step 1 of how a protected PR gets approved, and "Every review is recorded on its PR") say it the same way. What counts as the line, below, was settled in this PR's reviews; the owner merges the PR.

## Why

When a review is posted, the environment adds a line `_Generated by [Claude Code](https://claude.ai/code)_` after it. Of the 24 review comments with a `reviewed-sha:` line on #209 to #215 posted up to 2026-10-30 09:47 UTC, 9 end with that footer, not with `reviewed-sha:` (docs/mistakes/2026-10-30-review-footer-after-reviewed-sha.md). Read word for word, those reviews broke the rule, though each holds its record.

Once the line need not be last, which line counts has to be said. The first wording of this PR described it by Markdown form (inline backticks, a list item, a quote, a code block), and reviews found that description wrong for forms it did not name, such as an indented code block. A rule on the line alone has no such cases.

## Decided

Only where the line stands is loosened, and what counts as the line is made exact. A line counts when it is, in full, `reviewed-sha:`, one space and the 40-character SHA in lowercase (`^reviewed-sha: [0-9a-f]{40}$`), with nothing before or after it. CRLF line ends are read as LF, since they are how a body was typed, not a form of the line; without that, a REQUEST CHANGES written with CRLF would not undo an earlier approval. A comment with exactly one such line is a review of the head it names. A comment with two or more, as when it quotes another review's line, is not counted as a review: it approves nothing, and it undoes an earlier approval of each head it names, so a quote can stop the check but never pass it. Before this, the check also counted a line with no space after the colon, with text after the SHA, or with a longer hex string cut to 40 characters; it now does not. All 111 comments with a line the old check counted on #200 to #222, read on 2026-10-30 before 11:53 UTC, have exactly one line of the new form, so none of them changes.

A review still has its `reviewed-sha:` line with the head SHA it reviewed, in a comment on its PR; its first line still states the verdict; a protected PR's review is still made with fresh context by someone other than the author and reads the full diff at the current head; any push still makes an earlier `reviewed-sha:` stop counting; and a review with no such comment on GitHub is still never reported as a review.

`.github/workflows/protected-paths.yml` reads every line of a comment and applies this rule. packages/cli/test/judge-workflow.test.ts runs it on a review with the footer after its line (counted), on no line, on lines in other forms (backticks, list item, quote, indented, leading or trailing space, 39 or 41 hex digits, no or two spaces or a tab after the colon, uppercase; none counted), on comments with two lines (they approve nothing and undo an earlier approval of each head they name, whichever line comes first), and on reviews with CRLF line ends (counted, and a REQUEST CHANGES undoes an earlier approval). tools/records/test/records.test.ts holds the sentences of CLAUDE.md and docs/protected-paths.md that say this, word for word, so it fails when either file changes those sentences, for example back to "ending" or "last line". It also fails when a sentence about a review, a comment or a line anywhere in either file uses "ends", "ending", "end with", "last line" or "nothing follows", other than "which need not be its last line" and "CRLF line ends". A new sentence that says the same in other words is not caught; the review of the PR that adds it has to.

## Undo

A later decision of the owner's, with its own record. Requiring the last line again needs the posting environment to stop adding its footer, or every review to be edited after it is posted.
