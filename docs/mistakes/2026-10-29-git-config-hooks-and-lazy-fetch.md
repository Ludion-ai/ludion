# 2026-10-29 — The per-fix branch code left two ways for a repository's Git configuration to run a command

- **What happened.** The fresh-context review of bc60a34 (PR #204, comment 6495552957) found two ways in `packages/cli/src/security/branch.ts`. Nothing ran on a project.
  - **Config-named hooks.** Hooks named in configuration (`hook.<name>.command` with `hook.<name>.event`) are run by newer Git whatever `core.hooksPath` says. On the host's Git 2.55, the PR's exact calls ran such a `post-index-change` and `reference-transaction` hook.
  - **Lazy fetch.** In a partial clone whose HEAD commit is missing locally, `rev-parse HEAD^{commit}` fetched the commit and ran the repository's `remote.origin.uploadpack` command.
  - **The first fix was not enough.** It added `protocol.allow=never`. A repository's own `protocol.file.allow=always` wins over that. An automated security review of 58b3f24 pointed this out, and a probe in a container with no network showed that the uploadpack command still ran (docs/bench/2026-10-29-la-per-fix-apply/logs/transport-probe.log). The review of 58b3f24 (comment 6495987008) found the same hole, and added that Git versions before 2.44.0 without the 2024-05-14 security releases ignore `GIT_NO_LAZY_FETCH`. Each `protocol.<name>.allow=never` is now set on the command line, `GIT_ALLOW_PROTOCOL=none` is in the environment, and a partial clone is refused outright. The checks of the configuration run again before each branch.
- **Why.**
  - The defences were written against the hooks, fsmonitor, signing and filters known to Git 2.39, the version in CI and the Docker image. They were not written against what a newer Git on the owner's PC reads.
  - Reading an object was not seen as a way to reach the network.
- **Check:** `packages/cli/test/branch.test.ts`. "refuses a repository whose configuration names hooks" is version-independent: any `hook.*` setting refuses before any hook-running command. "never fetches a missing object with the repository's own transport command" refuses a partial clone, and has a control in which plain Git runs the command. The transport settings behind the refusal (`protocol.allow=never`, each `protocol.<name>.allow=never`, `GIT_NO_LAZY_FETCH=1`, `GIT_ALLOW_PROTOCOL=none`; each one alone stops the fetch on Git 2.39.5) are shown by the probe log above, not by a test.
- **Rule:** "Never run project-controlled or downloaded code or commands on the host."
