# 2026-10-29 — The per-fix branch code started git in the project's folder

- **What happened.** In PR #204 (LA), `packages/cli/src/security/branch.ts` ran the host's `git` with the project's folder as its working directory. On Windows, where the owner runs Ludion, the child's working directory is searched for `git.com` and `git.exe` before PATH. A project that ships its own `git.exe` would therefore have run it on the host at the first `rev-parse`, before any check. The fresh-context review of b572f81 (PR #204, comment 6495268563) found it, and nothing ran.
- **Then (2026-10-30).** The fix started Git from a temporary folder but still by bare name, so PATH chose it. `npx`, `npm exec` and package scripts put the project's `node_modules/.bin` first on PATH, a Composer script can add `vendor/bin`, and an activated venv adds `.venv/bin`. A `git` there ran on the host, and `node_modules` is never compared with HEAD, so the clean-tree check could not see it. The fresh-context review of 89fd0c8 (PR #204, comment 6503011718) reproduced it with a planted `node_modules/.bin/git`. Nothing ran outside that probe.
- **Why.**
  - The code closed every way the repository's Git configuration could start a command (hooks, fsmonitor, signing, filters), but not the way the program itself is found.
  - The hook test is skipped on Windows, and the Linux tests could not show a Windows-only lookup.
  - The first fix closed only the lookup that was reported (the working directory), not the lookup itself: the program was still named, not located.
- **Check:** `packages/cli/test/branch.test.ts` — "never runs a git program from the project's folder": with "." on PATH, which makes Linux look in the working directory as Windows does, a `git` in the project must not run, and a control shows it does when started there. Git now starts in a temporary folder Ludion owns and is given the repository with `-C`.
- **Check:** `packages/cli/test/branch.test.ts` — "never runs a git from a PATH folder inside the repository or a node_modules folder, and needs one outside": a `git` in the project's `node_modules/.bin` and `vendor/bin`, and in the repository's `.venv/bin`, first on PATH, must not run, and a control shows each runs when started by name; with only those on PATH, `--apply` refuses. Git now starts by the absolute path `findProgram` (packages/sandbox/src/docker.ts, PR #208) finds outside the repository, and `packages/cli/test/dependencies.test.ts` checks that a run with no such `git` refuses before any Docker work.
- **Rule:** "Never run project-controlled or downloaded code or commands on the host."
- **Not covered here.** `packages/sandbox/src/docker.ts` started `docker` the same way; PR #208 fixed it (docs/mistakes/2026-10-29-docker-started-from-the-project.md).
