# 2026-10-30 — Logs the docs cite were left out of the commit by .gitignore

- **What happened.** LB2a's commit 805ff90 ("LB2a: docs, mistakes record and the checks' logs") cited four logs in docs/bench/2026-10-30-lb-design/README.md and in PR #215's body (`logs/test-lb2a.log`, `logs/mutate-lb2a.log`, `logs/e2e-lb2a.log`, `logs/e2e-lb2a-php-maven.log`), and none of them was in the commit: `.gitignore` has `*.log`, and `git add` of the folder skipped them without a word. The files were on the lane's disk, so nothing there looked wrong, and CI passed, since no check read the docs' citations. The cloud review of #215 (comment 6518582507) found it at 805ff90; b6a7c88 added them with `git add -f`.
- **Why.** "The logs are committed" was taken from the commit message written before the commit, not from `git ls-files`. A record that cites a file had nothing to check that the file is in the tree; a local check could not see the gap either, because the ignored files were present on disk.
- **Check:** `tools/records/test/records.test.ts` — "docs/bench/ and docs/progress/ cite only files that are in the tree": every `logs/…` file a bench README cites, and every `docs/bench/…` path a bench README or a progress record from 2026-10-27 on cites, must exist; CI runs it on a fresh checkout, where an ignored log is absent.
- **Rule:** "Prefer a check that runs (a test, a CI job, a hook) to a rule someone has to remember."
