# 2026-10-30 — Delta v1's first execution stopped on a regular expression's stack

- **What happened.** Lane LD's first execution of `tools/backtest/src/delta-v1.ts` (commit 8d576eb, started 2026-10-30T00:19:00Z) stopped after about 1,200 of 1,348 pairs with `RangeError: Maximum call stack size exceeded`, exit 1, at 00:49:29Z. It wrote no result. The throw came from `/[A-Za-z0-9+/]{200,}/g` in `capabilityCounts` (delta.ts), on a code file of one fetched version.
- **Why.** V8's regular expressions backtrack, and a greedy repeat such as `{200,}` keeps one backtrack entry for each character it takes. On a run of several megabytes the backtrack stack overflows and V8 throws. The tests used runs of a few hundred characters, the size of the rule's threshold, never the size real bundles reach. The runner also had no guard, so one file's error ended the whole execution.
- **What changed.** The runs of rule 7 (hex, base64, `\x`/`\u` escapes and the hex part of `_0x` names) are scanned by hand, counting the same maximal runs as the expressions did. An analyzer error on one pair is recorded as undecidable for that pair, never as clean or flagged, and the run goes on. The definitions are unchanged. The next execution is the result, and the README reports the failed one.
- **Check:** `tools/backtest/test/delta.test.ts` — "counts runs of several megabytes without overflowing the stack" feeds runs of 4 to 8 MB to every rule-7 count.
