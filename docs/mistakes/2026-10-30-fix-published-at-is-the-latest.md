# 2026-10-30 — "The version taken's publish time" for a fix with two changes

- **What happened.** When `ludion patch` passes over a smallest fixed version (#209), README.md, packages/cli/README.md and docs/status.md said that the fix's `fix_published_at`, and the T of the time cap's rules 1 and 2, is the publish time of the version taken. LV2 (#212) added the same words to the receipt (`fix_published_note`: "this is the publish time of the version taken"). Both are the latest publish time among the fix's planned versions (exposure.ts `dependencyFixPublished`, time-cap.ts `timeCap`), so for a fix with two changes of one package, where only one change's version was replaced, the time can be the other change's. The cloud review of #212 found the documents' sentence (finding 3); the first review of #213 found the receipt's. LV3 (#213) corrected all four.
- **Why.** The sentence was written for the case of one change, and the test of a fix with two changes (#212) checked the versions but not the note or the documents. Receipts must show what was checked, not more.
- **Check:** `packages/cli/test/dependencies.test.ts` — every fix that takes a later version asserts the whole receipt sentence ("this is the latest publish time among the fix's planned versions, the version taken included"), and a mutation back to the old words fails it (docs/bench/2026-10-30-lv3-osv-publisher/scripts/mutate.mjs).
- **Rule:** "Receipts show what was checked, not more (and, once implemented, the exposure-time timestamps)."
