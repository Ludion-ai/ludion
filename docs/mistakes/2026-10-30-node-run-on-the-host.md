# 2026-10-30 — Agents ran node on the host, once loading a script from the repository

- **What happened.** Agents' briefs say project commands run only in Docker. On 2026-10-30, two lanes ran `node` on the owner's PC, outside Docker, 31 times in all. Times are JST.
  - **LI (PR #221), 19:46:11, once.** A replacement script the lane had just written to its session's temporary folder. It imported only Node's file-system module (no repository code, no `node_modules`, no network), checked that one fixed string occurred once in the file it was given, replaced it, and wrote the file back. It wrote `packages/cli/src/security/time-cap.ts` only (26 lines added, 6 removed). The lane's tests and mutations ran in Docker.
  - **LB2a (PR #215), 15:50:16 to 20:23:42, 30 times: 24 in its first round, 6 in its second and third.** 29 were edit scripts that imported only Node's file-system module. They wrote repository files (source and tests under `packages/cli/`, `action/start.sh`, docs, and the lane's mutation script) and files outside the repository (the lane's PR text, report and notes). The other one, at 15:56:44, was `node -e` with a dynamic `import()` of the mutation script in the repository (`docs/bench/2026-10-30-lb-design/scripts/mutate.mjs`), meant to check its syntax. Importing a module runs it: the script applied three mutations to `packages/cli/src/security/deliver.ts`, started `npx vitest` for each, restored the file each time, and stopped when its output pipe closed. The lane reported that the host had no vitest and that npx installed nothing (npx's cache had no newer entry), and that `deliver.ts` kept no mutation. Whether npx contacted the registry is not known.
  - The edit scripts loaded no dependency code. One call loaded and ran a script from the repository, one written by the lanes themselves. Other agents' temporary folders hold scripts of the same kind; whether those ran on the host has not been checked, and a file's presence does not show it ran.
- **Why.** The briefs' "project commands only in Docker" was read as builds, tests and experiments, not an agent's own edit scripts, and nothing refused `node` on the host: the Bash guard refuses backticks that bash would run, not `node`, `npm` or `npx`. Checking syntax by importing a module was a mistake in itself, since an import runs the module's top level (`node --check` only parses).
- **What changed.** The Check is to be `.claude/hooks/guard.mjs` refusing `node`, `npm` and `npx` on the host, with its test. `.claude/` is a protected path, so that is a protected PR the owner merges, and until it is merged this record points to the rule below. Meanwhile every agent's brief says: do not run node, npm or npx on the host, only inside Docker, and edit files with the editor's tools.
- **Rule:** "Never run project-controlled or downloaded code or commands on the host."
