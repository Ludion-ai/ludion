# 2026-10-30 — The judge read a malformed OSV answer as "no record"

- **What happened.** `osvIds` (packages/cli/src/security/npm-facts.ts), the judge's OSV batch reader since the judge v0 (#143, 2026-10-28), read each batch item as `(item?.vulns ?? [])`. An item that was `null`, a number, an object with an unknown key, or `{vulns: null}` became an empty list: "no MAL- record, no advisory" for that version. The scan's reader of the same API, `OsvClient.ids` (osv.ts), refuses all of these. In `ludion patch` the strict re-scan by `OsvClient.scan` still threw further on, but `ludion judge` on its own has no such re-scan, so an answer OSV never gave could pass gate 2's MAL- check there. `nextFix` (#209) used the same reader, so a version could be taken on such an answer; LV2 (#212) added a throw for a version with no answer, which could never run because `osvIds` always set one. The cloud review of #212 found it (https://github.com/Ludion-ai/ludion/pull/212#issuecomment-6514605931, finding 1). LV3 (#213) fixed it.
- **Why.**
  1. Two parsers of one OSV answer were written separately, and only one was written to refuse what it does not understand. A default (`?? []`) turned "not understood" into "nothing found", which is the fail-open direction.
  2. No test fed the judge's reader a malformed item, so nothing showed that the two readers disagreed. LV2's guard was tested by reading the code, not by an answer that reaches it.
- **Check:** `packages/cli/test/judge.test.ts` — "OSV's batch answers for the judge": `osvIds` throws on each malformed item, and for every item in a shared list it must agree with `OsvClient.ids` (both refuse it, or both read the same ids), so the two readers cannot drift apart unseen.
- **Check:** `packages/cli/test/candidate-judge.test.ts` — the patch's judge, which runs the same `gatherFacts` call and catch as `ludion judge`, is undecidable on a malformed item ("A lookup failed: Invalid OSV batch item").
- **Rule:** "Unknown inputs, unavailable sources, baseline failure, candidate failure and timeouts block updates."
