# 2026-10-30 — Reviews did not end with reviewed-sha:

- **What happened.** CLAUDE.md said every review is posted as a comment ending `reviewed-sha: <the head SHA reviewed>`, and docs/protected-paths.md said its last line is that line. On #209 to #215, 9 of the 24 review comments with a `reviewed-sha:` line posted up to 2026-10-30 09:47 UTC end with `_Generated by [Claude Code](https://claude.ai/code)_` instead: comments 6513625855 (#209), 6516135819 and 6516416032 (#210), 6513307861 and 6513399675 (#211), 6514605931 (#212), 6515878521 (#213), 6517309422 (#214), and 6518582507 (#215). Each still holds its `reviewed-sha:` line, and the `protected-paths` check's filter, which reads every line, finds it in each. The check reads comments only on a PR that changes a protected path, and of #209 to #215 only #211 does, so only #211's two (6513307861 and 6513399675) could have been read by the check itself.
- **Why.** The environment that posts a review adds that footer after the text it is given, so the reviewer cannot make `reviewed-sha:` the last line. Nobody compared the posted comments with the rule's wording, and the two files stated the rule separately, so changing one would not have shown in the other.
- **Check:** `tools/records/test/records.test.ts` — CLAUDE.md and docs/protected-paths.md must both say, word for word, that a review has the line `reviewed-sha:` (docs/decisions/2026-10-30-reviewed-sha-has-the-line.md); a file that changes those sentences, for example back to "ending" or "last line", fails it. A new sentence elsewhere in either file that says a review, comment or line "ends", is "ending", has a "last line" or that "nothing follows" fails it too; one that says the same in other words is not caught.
- **Check:** `packages/cli/test/judge-workflow.test.ts` — the `protected-paths` check is run on reviews with the footer after their `reviewed-sha:` line; a check that read only the last line would fail them. It also holds what counts as the line: exactly one line that is, in full, `reviewed-sha:`, one space and the 40-character SHA in lowercase.
- **Rule:** "Every review, protected path or not, is posted on its PR as a comment that has the line `reviewed-sha: <the head SHA reviewed>`; a review with no such record on GitHub is never reported as a review."
