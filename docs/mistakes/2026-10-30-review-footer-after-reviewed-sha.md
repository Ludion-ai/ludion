# 2026-10-30 — Reviews did not end with reviewed-sha:

- **What happened.** CLAUDE.md said every review is posted as a comment ending `reviewed-sha: <the head SHA reviewed>`, and docs/protected-paths.md said its last line is that line. On #209 to #215, 9 of the 23 review comments with a `reviewed-sha:` line end with `_Generated by [Claude Code](https://claude.ai/code)_` instead: comments 6513625855 (#209), 6513307861 and 6513399675 (#211), 6514605931 (#212), 6515878521 (#213), 6516135819, 6516416032 and 6517309422 (#214), and 6518582507 (#215). Each still holds its `reviewed-sha:` line, and the `protected-paths` check, which reads every line, counted them.
- **Why.** The environment that posts a review adds that footer after the text it is given, so the reviewer cannot make `reviewed-sha:` the last line. Nobody compared the posted comments with the rule's wording, and the two files stated the rule separately, so changing one would not have shown in the other.
- **Check:** `tools/records/test/records.test.ts` — CLAUDE.md and docs/protected-paths.md must both say a review has the line `reviewed-sha:` (docs/decisions/2026-10-30-reviewed-sha-has-the-line.md); a file that goes back to "ending" or "last line" fails it.
- **Rule:** "Every review, protected path or not, is posted as a comment on its PR that has the line `reviewed-sha: <the head SHA reviewed>`; a review with no such record on GitHub is never reported as a review."
