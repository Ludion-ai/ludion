# 2026-10-30 — The shadow's chain of runs was not started

- **What happened.** In Ludion-ai/ludion-shadow, each run of the shadow that commits starts the next one, with GitHub's hourly schedule as the fallback (#2, merged 2026-10-30 08:35 JST). The runs then in progress had started before the merge, from the old workflow, and started no next run; the last of them ended at 09:50 JST. Nobody started the first run of the new workflow by hand, and the schedule did not fire again until 14:52 JST, so the shadow recorded nothing for about five hours (09:50 to 14:52 JST). The run at 14:52 started the chain, and it has run since. A version published and removed in that window would not have been recorded.
- **Why.** The change was treated as done at its merge. A mechanism that keeps itself running starts only from a run that already has it, so the first run had to be started by hand, and someone had to confirm that the run after it started by itself. GitHub's schedule had already not fired for five hours on 2026-10-29 (12:17 to 17:17 UTC, as the shadow's workflow notes), which is why the chain was built, and it was still the only thing left to restart the shadow.
- **Lesson.** After changing how something keeps itself running, start its first run, and count the work done only when the next run has started by itself.
- **Check:** `tools/shadow/test/replay.test.ts` — a version that was never recorded is counted as a capture gap, never as judged, so a stop of the shadow shows in the count of (b). It does not catch the stop itself: the shadow repository's own schedule and the lesson above do.
