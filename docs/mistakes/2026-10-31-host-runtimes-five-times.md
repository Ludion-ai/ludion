# 2026-10-31 — Agents ran node, npm or python on the host at least six times, although their briefs said not to

- **What happened.** By 2026-10-31 an agent had started a JavaScript or Python runtime on the owner's PC (the host), outside Docker, at least six times: five counted by the owner's Claude chat (ludion-ops#1 comment 6542129458, 1), and a sixth found by the hourly audit in this PC's session records (comment 6544003261, 4), which no agent had reported. The file keeps its first name. Each agent's brief said to run such commands only in Docker. Times are JST.
  1. **10-28, `npm ci`.** One session ran `npm ci --no-audit --no-fund` three times (00:16:37, 00:22:22, 00:34:23) without turning off install scripts; esbuild's and workerd's install scripts are estimated to have run. Counted and described in docs/mistakes/2026-10-30-node-run-on-the-host.md (LAUD2), with every other host run since 10-28.
  2. **10-30, LAUD's python.** The audit lane LAUD ran `python -` with an empty heredoc (22:27:36) and `python3 --version` (22:55:02); neither had a script to run. Described in the same record.
  3. **10-31, the first hourly audit.** It ran `node -e "0"` once in its job's temporary folder, to see whether node was installed, before posting at 01:26 (comment 6527803283, finding 7). The exact time is not in the comment (不明).
  4. **10-31, R215.** The review lane of #215 ran `cd …/tmp/mut && node -e "1"` once, then `command -v node` (its report; Grok's comment 6530307303 at 03:20). Its brief had named the rule word for word: do not run node, npm, npx … on the host, and use `command -v` to check (audit comment 6530612087, finding 3).
  5. **10-31, LIMGV.** The lane of #239 ran its own edit script (a `.mjs` in its job's temporary folder) once with the host's node, to rewrite `node.ts`. It reported this itself (Grok's comment 6542109824 at 19:14) and says the script was neither project code nor downloaded code; R239 was asked to check what the rewrite put in the diff.
  6. **10-31 14:26:09, LMR1.** The lane of #236 ran `python3 --version 2>/dev/null; echo` in the host's Bash, after writing a note with `cat > $CLAUDE_JOB_DIR/tmp/simplify.txt <<'EOF'`; the call returned no output. On this PC `python3` is the WindowsApps alias of the App Installer, so most likely no Python code ran (the audit's estimate). Nobody reported it; the audit found it by searching the session records for those names as the first word of a command, a count that also missed runs 3 and 5, so the true number is not known (不明).

  Only the first ran a downloaded package's code (the install scripts, estimated). Three (3, 4, 6) only checked that a program exists; one (5) ran the lane's own script.
- **Why.** A rule in a brief has to be remembered at the moment an agent reaches for the quickest tool: running a program to see whether it exists, or a short script to rewrite a file. Nothing refused the command. `.claude/hooks/guard.mjs` refused deploys, secrets, force pushes, downloads piped into a shell and backticks, not runtimes. The record of 2026-10-30 planned this check, but the guard's protected PR waited behind others, and the runs went on: the last three came after that record entered main (#223, 10-30 22:40). CLAUDE.md, How we work: "Prefer a check that runs (a test, a CI job, a hook) to a rule someone has to remember."
- **What changed.** The guard now refuses node, npm, npx, pnpm, yarn, bun, deno, tsx, vitest, python, python3, py, pip, uv and corepack (and other names of the same programs) on the host: by name or full path, through `cmd /c`, `Start-Process`, PowerShell's `&`, a shell's command string, `eval`, a heredoc fed to a shell, `$( )` and the other forms in docs/decisions/2026-10-31-lguard-host-runtime-guard.md. It also refuses reading a third-party repository's files on the host (`gh api … contents`, `compare`, `commits/<sha>`, `tarball`, cloning, raw downloads). Its message gives the Docker command to use instead. Commands run inside `docker run`, `git`, `gh` on Ludion-ai's repositories, `claude`, and text that only mentions a name stay allowed. The six commands, as typed, are in the tests. A guard that fails or cannot start now stops the call (`"onFailure": "block"` and a try/catch), and Edit, Write and NotebookEdit cannot change `.claude/` in any worktree.
- **Remaining holes** (whether to close them is the chat's decision):
  - **A script file's contents are not seen.** For `sh x.sh`, `bash x.sh`, `pwsh -File x.ps1` or `cat x.sh | sh`, the hook sees the shell and the file's name; a `node` written inside the file runs (audit comment 6542250801, finding 5).
  - A program named through a variable or a lookup, a node or Python program installed on the PATH under its own name (`tsc`, `wrangler`), and other ways to read third-party files; listed in the decision record.
  - Programs that run other programs and are not read: `awk` with `system()`, GNU `sed`'s `e` command, `perl -e` (audit comment 6544003261, 2); and writes to `.claude/` from Bash or PowerShell (`>`, `cp`, `sed -i`, git), which the Edit/Write rule does not see. The chat plans an allow list instead (LGUARD2).
  - **A runtime inside backticks** is refused only by the backtick check, whose reading of quotes still differs from bash's after a `${…}` holding quotes inside double quotes, or a `case` pattern's `)` inside `$( )` (two open findings of the automated security review; the decision record).
  - The hook refuses; it does not count. A run that slips past it is seen only if the agent reports it, or by a record of every process started (Windows event 4688 with command lines, or Sysmon event 1), which is the PC's setting and the owner's decision.
  - The hook itself is node on the host (`.claude/settings.json`), the owner's tool and not an agent's command (comment 6528291928, 5).
- **Check:** `.claude/hooks/guard.test.ts` — the six commands and the other forms are refused; Docker, git, gh, claude and mentions are allowed.
