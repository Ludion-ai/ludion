- **Why.** A rule in a brief has to be remembered at the moment an agent reaches for the quickest tool: running a program to see whether it exists, or a short script to rewrite a file. Nothing refused the command. `.claude/hooks/guard.mjs` refused deploys, secrets, force pushes, downloads piped into a shell and backticks, not runtimes. The record of 2026-10-30 planned this check, but the guard's protected PR waited behind others, and the runs went on: runs 3 to 6, and LAUD's `python3 --version` at 22:55:02, came after that record entered main (#223, merged 2026-10-30T13:40:46Z, 22:40 JST), so at least four (R241's review, comment 6545725318, 4). CLAUDE.md, How we work: "Prefer a check that runs (a test, a CI job, a hook) to a rule someone has to remember."
- **What changed.** The guard now refuses node, npm, npx, pnpm, yarn, bun, deno, tsx, vitest, python, python3, py, pip, uv and corepack (and other names of the same programs) on the host: by name or full path, through `cmd /c`, `Start-Process`, PowerShell's `&`, a shell's command string, `eval`, a heredoc fed to a shell, `$( )` and the other forms in docs/decisions/2026-10-31-lguard-host-runtime-guard.md. It also refuses reading a third-party repository's files on the host (`gh api … contents`, `compare`, `commits/<sha>`, `tarball`, cloning, raw downloads). Its message gives the Docker command to use instead. Commands run inside `docker run`, `git`, `gh` on Ludion-ai's repositories, `claude`, and text that only mentions a name stay allowed. The six commands, as typed, are in the tests. A guard that fails or cannot start now stops the call (`"onFailure": "block"` and a try/catch), and Edit, Write and NotebookEdit cannot change `.claude/` in any worktree.
- **Remaining holes** (whether to close them is the chat's decision):
  - **A script run by its own path is not seen** (`./tools/run.mjs`, `./x.py`, `.\x.py`, `& .\tools\run.py`, `Invoke-Item x.py`, `Start-Process x.py`, `cmd /c x.py`, `start x.py`): Git Bash reads a `#!/usr/bin/env node` line, so `./x.mjs` may start the host's node (the audit's estimate, not tried). Of 34 forms that start a runtime, the guard at bfbecf9 refused 22 and let 12 through (audit comment 6545633020, 3).
  - **A script file's contents are not seen.** For `sh x.sh`, `bash x.sh`, `pwsh -File x.ps1` or `cat x.sh | sh`, the hook sees the shell and the file's name; a `node` written inside the file runs (audit comment 6542250801, finding 5).
  - A program named through a variable or a lookup, a node or Python program installed on the PATH under its own name (`tsc`, `wrangler`), and other ways to read third-party files; listed in the decision record.
  - Programs that run other programs and are not read: `awk` with `system()`, GNU `sed`'s `e` command, `perl -e` (audit comment 6544003261, 2); and writes to `.claude/` from Bash or PowerShell (`>`, `cp`, `sed -i`, git), which the Edit/Write rule does not see. The chat plans an allow list instead (LGUARD2).
  - **A runtime inside backticks** is refused only by the backtick check, whose reading of quotes still differs from bash's after a `${…}` holding quotes inside double quotes, or a `case` pattern's `)` inside `$( )` (two open findings of the automated security review; the decision record).
  - The hook refuses; it does not count. A run that slips past it is seen only if the agent reports it, or by a record of every process started (Windows event 4688 with command lines, or Sysmon event 1), which is the PC's setting and the owner's decision.
  - The hook itself is node on the host (`.claude/settings.json`), the owner's tool and not an agent's command (comment 6528291928, 5).
