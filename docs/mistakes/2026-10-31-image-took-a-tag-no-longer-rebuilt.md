# 2026-10-31 — The official image moved to a tag that Docker no longer rebuilds

- **What happened.** LNODE's item 5 (docs/decisions/2026-10-31-lnode-node-image.md, merged in #231) and LPHPV (docs/decisions/2026-10-31-lphpv-php-security-release.md, merged in #237) moved an official Node.js or PHP image to the newest *security* release of its line, and never to a later release that was not marked security. docker-library rebuilds only a line's newest tag, so that is the only tag that gets OS-package fixes. When the line's newest release was not a security release, Ludion put the project on a tag that no longer receives them, and did not move it while that lasted, because it moved only when a new security release came out. The audit in ludion-ops#1, comment 6540622832, item 1, counted 216 of 366 such days for PHP 8.4 and 297 of 366 for Node.js 24 in the year to 2026-10-31 (the audit's numbers, not recounted here). The brain's comment 6540818608, item 1, called its acceptance of the change an error, and comment 6541349120 fixed the rule as a state: the image moves to the newest release of its line that Docker still builds in its variant (docs/decisions/2026-10-31-limgv-image-newest-built-release.md).
- **Why.** The Goal's "smallest fixed version" was read as it is for a package, whose contents never change after it is published. Nobody checked how the official images are rebuilt. PHP's earlier choice, the branch's newest release, was right for this reason, but no record said why, so nothing stopped the change.
- **Check:** `packages/cli/test/node-image.test.ts` (node:22.23.4, a security release that is no longer the line's newest, moves to 22.23.5, and moves once 22.23.5 is listed)
- **Check:** `packages/cli/test/security.test.ts` (php:8.4.28 and php:8.4.29 move to the branch's newest release, 8.4.30, which is not tagged security)
