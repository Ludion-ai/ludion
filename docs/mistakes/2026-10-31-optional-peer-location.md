# 2026-10-31 — The PR job let another package in at an optional peer's location, where the texts said it checked

- **What happened.** On main after #215 (355a91c), audit 6541743253 (item 1) found that the PR job's check of package-lock.json took an added package at the location of a moved package's optional peer without checking it. Its walk of what the moved and added paths require (deliver.ts, `npmLockProblem`) read every `peerDependencies` name (judge.ts, `DECLARED`), optional ones included, so such a package counted as required; and the requirement check (judge.ts, `requirementsMet`) left optional peers out, so nothing checked that it was the package the spec names, or in range. With node-fetch 2.6.1 -> 2.6.7 (an optional peer `encoding ^0.1.0`, which node-fetch loads when it is there), an added `evil-pkg@1.0.0` at node_modules/node-fetch/node_modules/encoding or at node_modules/encoding, and an `encoding@9.9.9`, passed `contentProblem`, run in Docker. The PR body, both READMEs, docs/status.md, docs/decisions/2026-10-31-lock-corpus-alias.md and the Check of docs/mistakes/2026-10-30-deliver-checks-read-past-git.md all said that an added package is one its requirer requires, as that package, in range: true of every requirement but an optional peer.
- **Why.** "Required" was read in two places with two meanings: the walk counted optional peers as requirements, the requirement check did not. Neither was compared with what npm does with an optional peer (npm 12.2.1 never adds a package for one, leaves a package that only optional peers reach extraneous and prunes it, and refuses with ERESOLVE a fix whose optional peer finds another package). The corpus's changed variants (V3 in particular, docs/bench/2026-10-31-lb2a-npm-corpus/README.md) put another package only at locations a range requires, so no test had an optional peer's location.
- **Fixed in the same PR** (LFLAGS, docs/decisions/2026-10-31-lock-flags-from-graph.md, section 1): the walk follows only what npm installs (judge.ts, `requiredNames`: no optional peer), so a package reached only through one is stray; and the requirement check, in `ludion judge`, npm `patch`'s judge and the PR job, holds an optional peer that the lookup finds to the package its spec names, in range, as npm 12.2.1 does. The audit's B, C and E, V3's form at the optional peer (P), and the real package nested where npm would not put it (R) are fixtures, with npm 12.2.1's and npm 11.19.1's reports on them.
- **Check:** `packages/cli/test/deliver.test.ts` — "npm: an optional peer adds nothing, and where the lock has one it is the package its spec names, in range (audit 6541743253, item 1)".
- **Check:** `packages/cli/test/npm-corpus.test.ts` — "X4: npm 12.2.1 refuses the fix whose optional peer finds another package (ERESOLVE), so rule 2 refuses nothing npm writes" and "P1: npm reports C and E, not B, P or R; Ludion's requirement check finds B, C, E and P unmet, and R met".
- **Check:** `docs/bench/2026-10-31-lflags/scripts/mutate.mjs` — a mutation for each of the two rules.
- **Rule:** "Receipts show what was checked, not more (and, once implemented, the exposure-time timestamps)."
