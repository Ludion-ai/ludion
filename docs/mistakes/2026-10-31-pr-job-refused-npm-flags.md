# 2026-10-31 — The PR job refused a real npm fix for the flags npm moves, and with it every PR of the run

- **What happened.** In #215 (LB2a), the PR job required every package-lock.json entry a fix neither moves nor adds to be exactly as at the base, flags included. The R lane's review of e9559e4 (comment 6538813186, B1) ran npm 12.2.1 as `patch` does on node-fetch 2.6.1 -> 2.6.7: the fix requires a dev-only whatwg-url, so npm drops `dev` from whatwg-url, tr46 and webidl-conversions. `patch` applied the fix and main's PR job opens it; #215's refused it, and since one content problem refuses the whole artifact, no PR opened for any fix of the run, on every run. The texts called this "fails closed" and did not say it stops every PR.
- **Why.** The strict rule was written from what a forged lock could do, not from what npm writes for a real fix. The npm corpus checked the reader (judge.ts) against locks npm wrote, but the PR job's own per-path checks were never run on a fix npm wrote. And the cost of one refusal (every PR of the run) was not weighed when the rule was called fail-closed.
- **Fixed in the same PR.** docs/decisions/2026-10-31-lock-flags-only.md (the brain's option (a)): such an entry may differ in `dev`, `optional`, `devOptional` and `peer` only. B1's pair, as npm 12.2.1 wrote it, is a fixture, and the PR job is tested to open it. The flags are not yet checked against what npm computes; docs/status.md lists it.
- **Check:** `packages/cli/test/deliver.test.ts` — "an npm fix that npm 12.2.1 writes with other entries' flags changed is opened (review 6538813186, B1)" and "npm: an entry the fix does not plan may differ from the base in its flags only (review 6538813186, B1)".
- **Check:** `packages/cli/test/npm-corpus.test.ts` — "N2: B1's node-fetch fix, which npm 12.2.1 wrote and reports nothing new on, leaves no requirement unmet".
- **Check:** `docs/bench/2026-10-30-lb-design/scripts/mutate.mjs` — a mutation for each part of the rule.
