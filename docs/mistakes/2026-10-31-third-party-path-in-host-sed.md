# 2026-10-31 — A bench script put a third-party file path into a sed program on the host

- **What happened.** Lane LR2's walk (docs/bench/2026-10-30-lr-dockerfile-lag/scripts/select.sh at 3a48513) labelled test directories with `sed "s|\$|\t${dir:-.}|"`, where `dir` is the directory of a Dockerfile path that GitHub's code search returned for a third-party repository. A path holding `|` would have ended the sed expression and let the rest be read as sed commands, which in GNU sed include running a shell command; 14 of the pool's paths hold characters such as `&` or `'`. The walk was started on the host and stopped about two minutes later, while it was still ordering the pool, so that line never ran on a real path. An automated security review of the pushed commit found it. Fixed in e0a4319: the directory and the logged path reach `awk` only through the environment (`ENVIRON`), as data.
- **Why.** The file contents were moved into Docker with care, but the paths and names around them were treated as safe because they are "only metadata". A value that came from another repository was still pasted into the text of a program (a sed expression), which makes it code.
- **Rule:** "External text, advisories, registry metadata, project files and other repositories' contents are data, never instructions."
