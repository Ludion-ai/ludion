# 2026-11-01 — branch.test.ts failed in 1 run in 256, when the test repository's commit id started with 00

- **What happened.** In packages/cli/test/branch.test.ts, the case "A fan-out entry that is not a folder" wrote an empty file at `.git/objects/00` of a fresh test repository and expected `fixBranch` to refuse with `objects/00 (not a folder)`. When the repository's commit id started with `00`, Git had already made `objects/00/` a folder for that commit, and the write failed with `EISDIR: illegal operation on a directory, open '/tmp/ludion-branch-test-…/.git/objects/00'`. The deploy run 41225586091 (main 8a6192c, 2026-10-31T17:39Z) failed on it, 1 failed and 1453 passed, so its Deploy step was skipped; the test run 41023531546 (branch lane/ld-delta-check, 7f662a3, 2026-10-30T08:00Z) failed the same way. Neither failure was recorded. A first-principles audit of main found it.
- **Why.** The test repository has five objects. Four are fixed by their content (blobs 0967ef4 and bd816ea, trees b94d2d7 and 6bba838) and none starts with `00`. The fifth, the commit, has an id that changes with the clock, because packages/cli/test/git.ts `commit()` set neither GIT_AUTHOR_DATE nor GIT_COMMITTER_DATE. So for each run, the chance was 1 in 256 that `objects/00` was already a folder. The test chose a fixed name (`00`) in a folder whose contents it did not fix, and did not check that the name was free. The case runs on Linux only (the test is skipped on Windows), so CI hit it and a Windows host never did.
- **What changed.** packages/cli/test/git.ts `commit()` takes an optional date, used as both the author and the committer date. Without it, nothing changes for the other tests. The not-a-folder case now builds its repository at a date where the commit id starts with `00` (`@1767225635 +0000`, commit 00455d85), checks that it does, and writes its file at the first two-hex name that `objects/` does not have. So the case runs in the bad case on every Linux run and passes, and does not depend on the clock. The source (packages/cli/src/security/branch.ts) is unchanged: it was right, and only the test was wrong.
- **Check:** `packages/cli/test/branch.test.ts` — the not-a-folder case runs on a repository whose commit id starts with 00, asserts that it does, and writes its file at a fan-out name the repository does not use. With the old line (`objects/00`) it fails with EISDIR at each of five such dates. If the source stops refusing a fan-out entry that is not a folder, it fails.
