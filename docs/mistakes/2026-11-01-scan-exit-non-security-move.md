# 2026-11-01 — `ludion scan` exited 1 for an image move with no security release, while it waited too

- **What happened.** Since #239 (LIMGV), an official PHP or Node.js image check has a candidate also when no newer security release lies between: while its 72-hour wait runs (`wait`) and after it (`update_available`, `security_releases` empty). `ludion scan` counted every candidate as a finding: packages/cli/src/security/cli.ts gave exit 1 and packages/cli/src/security/scan.ts `attention_required` whenever `candidate !== null`. So a CI job that gates on `ludion scan` failed each time the line had a newer release that is not a security release, during the wait included, while both READMEs said exit 1 means "a known vulnerability or a PHP or Node.js security release", and the text line printed `update <version>` with no word of the wait or that it is not a security release. Over the year to 2026-11-01, PHP 8.4 had 7 such releases and Node.js 24 had 12 (the audit's table). The first-principles audit (ludion-ops#1, comment 6545633020, item 2) found it.
- **Why.** LIMGV widened what a candidate means (a move with no security release, and a new `wait` status) and changed the scan's lookup, `patch`, `deliver`, exposure time and their texts, but not the two places that turn a candidate into an exit code, which still read "a candidate is a security update" from before #239. No test looked at scan's exit code for such a move; the one exit-code test of a move (node-image.test.ts, the byte-order-mark test) had a security release between, so it exited 1 under both readings.
- **What changed.** `securityMove()` in scan.ts counts an image check only when it has a candidate and at least one newer security release; cli.ts's exit code and scan.ts's `attention_required` both use it. The text line says `newest release <v> of the line (no newer security release); waits until <t>` (or `its wait ended <t>`). The READMEs say such a move is shown and does not change the exit code (docs/decisions/2026-11-01-scan-exit-non-security-move.md). The site's sentences are fixed in a separate PR, since merging apps/site deploys ludion.ai.
- **Check:** `packages/cli/test/scan-exit.test.ts` — for the PHP and the Node.js image, a move with no newer security release exits 0 with `no_known_updates` while it waits and after its wait, with the text that says so; a move with a security release between still exits 1 with `attention_required` and `update <v>`; beside an unsupported inventory or with a failed check, scan still exits 2.
