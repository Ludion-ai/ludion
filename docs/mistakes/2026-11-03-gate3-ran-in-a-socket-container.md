# 2026-11-03 — A lane ran node in a container given the host's Docker socket, because its brief left no other way

- **What happened.** To measure gate 3 on real Docker, the lane LG3 ran `node` in a container started with `-v /var/run/docker.sock:/var/run/docker.sock`: six calls on 2026-11-02 between 08:25:24Z and 08:46:02Z, and eight starts, since the last call was a loop of three that was stopped during its third. The container ran as root, with the network on and without `--read-only`, with `--memory 1g` and with `packages` and `examples` mounted `:ro`. It ran the lane's `packages/cli/test/gate3-docker-run.ts` and, once, `node -v`. No dependency was installed in it, and what ran there imports Node's own modules and Ludion's, no package; next and lodash ran only inside the containers that script started. No harm is known. The lane's own report said it used the socket; the summary passed on from that report did not, and an audit of the session records found it. Installs in a socket container are an earlier case, with its own record: docs/mistakes/2026-11-01-docker-sock-npm-ci.md.
- **Why.** The brief contradicted itself. It asked for three measurements on the development machine's Docker and forbade `node` on the host, and `judgeGate3` is a node program that starts Docker, so the socket was the only way left. The brief's line on the socket named `npm ci`, `npm install`, `npx` and install scripts, and the lane read its script as allowed under that line. By the sentence below, such a container counts as the host, so by that reading `node` ran on the host eight times. Nothing refused it: the host guard does not read a `docker run`'s mounts (docs/status.md, "A container that counts as the host").
- **What changed.** A decision after this: no work on the development machine uses a container given the socket, and gate 3's real run through Docker belongs in C4's VM, where no credentials are.
- No check that runs catches this yet. The rule below is one someone has to remember.
- **Rule:** "A container given the Docker socket, or a writable mount of the work tree, can act on the host, so it counts as the host."
