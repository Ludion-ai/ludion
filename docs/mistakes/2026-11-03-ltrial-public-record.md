# LTRIAL's first records: text from a private repository, a wrong count, and a record in a check's place

- **What happened.** The fresh-context review of PR #278 at d6471bd found three things in LTRIAL's records. The saved lists of ludion-trial's PRs, committed to this public repository, held the body of PR 7, a PR of that private repository about how the work is run. docs/status.md called the copy these runs used a third, when six copies had already run there and opened PRs 1 to 6. C6's new row named a record in its Test cell, so the table counted it like a row with a check, though nothing runs it again and a later commit is not covered. The first fix, at 9f1e34d, set that cell to Not written, which counts the row as having nothing; it was decided on 2026-11-03 that a hand-run record counts once, on the SHA that ships. The second fix, at 0aaa5b5, wrote the cell as a record of one version and SHA and counted it as filling the row. The review of that head found that this counts a commit that ships to nobody, six files of the code that ships having changed since, and that `expect(kinds.none.length).toBeGreaterThan(0)` in the test fails in the state C6 aims for, when no row has no check.
- **Why.** The lists were saved whole, and the scan before the commit looked for tokens and email addresses, not for text about the work; nobody read the body of a PR this lane did not open. "Third" was counted from the sentence beside it, which names two copies, and not from the list of PRs the lane had already printed. The row's Rule cell said it is not a test, but `problems()` in tools/records/test/c6-table.test.ts and the paragraph above the table read only the Test cell, and knew two kinds where there are more, so the form said the opposite of the words. The second fix said in a sentence that a later commit is not covered, but the condition of the release read only Not written and 未実装, so nothing moved the row when the commit was not the one that ships. The assert described today's table instead of what must hold in every state.
- **Fixed in the same PR.** PR 7's body is replaced in the three lists (docs/bench/2026-11-03-ltrial/README.md says so), and docs/status.md gives the six copies. The row's Test cell says it is a hand-run record not yet on the SHA that ships, with the version and SHA of its last run, and the row is not met. The test tells a check that runs, a hand-run record on the SHA that ships, one not yet on it and no check apart, counts the last two as not met, passes a hand-run record's form only when its record is there and names that version and SHA, and refuses a record under docs/ written as a check. The assert on rows with no check is gone, and a test runs the table in the state C6 aims for. No test shows that a SHA is the one that ships: a change to a row's cell and the test's list is seen in review, not stopped.
- **What stays.** The earlier commits of this PR's branch still hold PR 7's text; whether to do more about it is the owner's. No check catches text about the work in a saved log, so that part of this mistake can pass again until one exists. Such a check is proposed in the lane's report and not built here: earlier records on main name the same private repository, so a plain search would fail on them.
- **Check:** `tools/records/test/c6-table.test.ts`
- **Rule:** "Prefer a check that runs (a test, a CI job, a hook) to a rule someone has to remember."
