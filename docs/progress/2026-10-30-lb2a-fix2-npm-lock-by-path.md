# 2026-10-30 — LB2a, second and third rounds: the npm lock checked by install path

PR #215 (branch `lane/lb2a-deliver-checks`), after the cloud review's REQUEST CHANGES (comment 6518582507 at b6a7c88), then the lane's review's (comment 6519780482 at 7d25696). Detail: docs/bench/2026-10-30-lb-design/README.md, "LB2a, second round" and "LB2a, third round".

**Changed.** The PR job reads every package-lock.json key through the judge's own `lockKey` and refuses a key that is not the root or an install path (B1: `aaaaaaaaaaaaminimist` had counted as minimist). The npm lock check is by install path: each path where the base has the receipt's package at `from` moves to `to` in place; each added path is required by a moved or added one, as the package named and at a version in its range; every other entry stays as at the base; and the root and every unmoved entry load each requirement from the same path as before (N-a). Each moved or added entry's requirements, `os` and `cpu` must be what the registry lists, so "required" rests on the registry's data, not the artifact's. fsck runs once per artifact (N-c). Packagist PKSA IDs are read only in the PR job's form (N-d). Tests for R4, R5 and R16 (N-b). A records test fails when a cited log or bench file is not in the tree.
