### The risk of forms B and B2, and what was decided after the trial

A green PR from forms B and B2 is not a reason to use them. In both, Ludion's PR job starts the project's own CI on Ludion's branch, and that CI runs the candidate. The audit put it this way (ludion-ops#1, quoted word for word in the brain's answer 6533365853):

> 「プロジェクトの CI で候補を動かすと、候補はプロジェクトの秘密の値とネットを持って、人が見る前に動く。Dependabot は PR の実行に秘密の値を渡さない。今の CLAUDE.md:44 と :53 は、これを禁じている」

In English: when the project's CI runs the candidate, the candidate runs with the project's secrets and network, before any person has looked at it. Dependabot does not give secrets to the runs of its PRs. CLAUDE.md:44 ("A job that runs candidate code has no write permission and no secrets") and :53 (candidate code runs only through packages/sandbox, with no network) forbid it.

- Ludion's PRs come from branches of the same repository, so CI on them gets the repository's secrets and network. A PR from a fork, or from Dependabot, does not.
- Suppose a hijacked legitimate publisher's version, with unchanged provenance, gets through the wait. It would then run in a CI that holds secrets, before anyone reviews it.
- In ludion-trial nothing was exposed: the repository has no secret and no environment (`total_count` 0 for both at 21:20Z, logs/secrets-list-2026-10-30T2120Z.json and logs/environments-2026-10-30T2120Z.json; the secrets count was also 0 at about 19:08Z, unsaved), and the candidate was the official PHP 8.4.27 image.

Decided by the brain after the trial (6533365853, item 1):
- **Forms B and B2 do not go into the template.** Ludion's PR job is never given `actions: write`.
- **Form C is the default.** Ludion's own validation result goes on the commit as a status, with `statuses: write` only.
- **The project's CI is used only when it is confirmed** that the secrets sit in an environment limited to the default branch and cannot be reached from Ludion's branches. That confirmation needs a secret and an environment in ludion-trial, which tonight's rules forbid. The steps are in the next section, for the owner. Unconfirmed means not used.

Form A is in the same position: if a person approves its `action_required` run, the project's CI runs the candidate with the same secrets and network.
