# 2026-11-01 — LSCAN404: `ludion scan` keeps a newer security release when Docker Hub has no tag for the move

**Lane LSCAN404**, from main 71fc751, for a fact error found by a first-principles audit on 2026-11-01: with a newer security release between, but no tag on Docker Hub for the line's newest release in the Dockerfile's variant, `ludion scan` said `unavailable`, exited 2 and did not say the security release existed, while both READMEs (line 123) say scan exits 1 for "a PHP or Node.js security release newer than the Dockerfile's version". Mistake: docs/mistakes/2026-11-01-scan-missing-tag-dropped-security-release.md. No decision record: the wait and the choice of the version a move goes to are unchanged.

## What changed

- packages/cli/src/security/php.ts: on Docker Hub's 404 for the move's tag, `imageMove` throws `MissingImageTag`, which keeps the line's security releases newer than the Dockerfile's version (`security_releases`, newest first) and, when there is one, names it before the reason that was there: `PHP 8.4.29 is a security release newer than 8.4.28; Docker Hub has no php:8.4.30-cli, ...`, or `Node.js 22.23.4 and 22.23.2 are security releases newer than 22.11.0; ...`. With none, the reason is word for word as before.
- packages/cli/src/security/scan.ts: such a stop becomes `{ ecosystem, error, security_releases }`; any other failure stays `{ ecosystem, error }`. `found()` says what scan exits 1 for: a known vulnerability, a counted image move (`securityMove()`, unchanged), or this stop with at least one security release. `attention_required` is unchanged (a failed check already counted).
- packages/cli/src/security/cli.ts: scan's exit code uses `found()`; this stop's line goes to standard output as `<php|node>: <reason>`, without "unavailable". Other failed checks print as before.
- README.md and packages/cli/README.md, line 123: not changed. Their sentence ("Scan exits 1 when it finds a known vulnerability or a PHP or Node.js security release newer than the Dockerfile's version, 2 when it finds none but something still needs attention (a failed check, ...)") now holds in this case too.
- docs/status.md: item 4 and its date line.
- `patch` still stops in this case (no move is decided); its reason now names the security releases too.

## Tests (packages/cli/test)

- scan-exit.test.ts, 8 new (PHP and Node.js each): with a security release between and the tag missing, scan exits 1 at both clock times, the text line names the release and the missing tag, nothing says "unavailable", the check is exactly `{ ecosystem, error, security_releases: [the release] }`, and `scan --json` gives `attention_required`, the error and `security_releases`; with none and the tag missing after the wait, scan exits 2 with `<ecosystem>: unavailable — <the reason as before>` and the check has no `security_releases` (text and `--json`); with none while the wait runs, Docker Hub is not asked and scan exits 0.
- node-image.test.ts, 3 new: the stop is a `MissingImageTag` with the exact reason for two, one and no newer security releases, and `security_releases` lists them.
- The existing reason tests (security.test.ts:115, node-image.test.ts:97, security.test.ts:260) are unchanged and pass: each checks a part of the reason that is still there.
